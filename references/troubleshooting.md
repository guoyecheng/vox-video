## 三个"开渲前"的自查

渲整片要几分钟到几十分钟。下面三个脚本在渲之前就能把大部分错挑出来：

| 脚本 | 什么时候跑 | 挑什么错 |
|---|---|---|
| `preflight.py` | 配音之前 | id 重复、kind 拼错、缺必填字段、图文件不存在、层少 `y`、枚举值写错、字体缺失 |
| `stills.py` | 闸门 0（效果图）/ 渲染之前（闸门 B） | 文字溢出、字幕压主体、转场接缝、数字和标签、配图跑题、图里冒出文字 |
| `check_motion.py --baseline` | 渲染之后 | 哪几拍变死了（拿旧成片逐拍比） |

`preflight.py` 的 kind / transition 名单是从项目源码 `src/timeline.ts`、`src/transitions.ts`
里读的，改了组件不用同步改脚本。

## 画面单调

先跑数字，别凭感觉：

```bash
python "<skill>/scripts/check_rhythm.py" --project "<项目>" --src "<模板 src>"
```

它会报出：同一种视觉连续出现几次、某种视觉占比、视觉种类数够不够、
转场是否相邻重复、全画面冲击是否超预算、字号是否低于可读下限。

**判据**（默认阈值，脚本里可改）：

| 指标 | 上限 | 为什么 |
|---|---|---|
| 同一种视觉连续出现 | ≤2 拍 | 连续同款 = 节奏没变 |
| 单种视觉全片出现 | ≤4 次 | 再多观众就"知道下一拍长什么样了" |
| 视觉种类数 | ≥ 拍数 ÷ 2 | 低于这个必然重复 |
| 相邻两拍转场 | 不重复 | 重复等于没转 |
| 全画面 `impact`/`flash` | ≤3 处，间隔 ≥3 拍 | 整层冲击会疲劳；元素层的小反应不受限 |
| 辅助文字字号 | ≥32px @1080p | 低于此值在手机小窗里读不清 |
| 主叙事文字字号 | ≥56px @1080p | 同上，中文笔画密度高更早糊 |
| 字幕字号 | ≥60px @1080p | 全片读得最久的一层，单行纸带约 215px |

对比度、安全区、停留时间的完整口径见 `readability.md`。

**"有效字高" ≠ 代码里的 `fontSize`**：如果祖先链上有 `transform: scale()`
或 3D 透视，实际渲染出来的字会更小。验收要量渲染帧上的实际像素——
最省事的办法是抽一帧缩到 480px 宽（模拟手机小窗）看看还读不读得清。

**读不到的文字宁可删掉**，不要靠缩小来"塞进去"。文字只有两态：
要读（达标字号 + 足够对比度）和纹理（装饰性小字，明显虚化降亮度），
不存在"重排了但仍读不清"的中间态。

## 音画不同步

先跑工具，别先猜：

```bash
python "<skill>/scripts/verify_sync.py" --project "<项目>"
```

它会输出逐拍误差表，并区分两种完全不同的问题：

| | 症状 | 含义 | 处理 |
|---|---|---|---|
| **系统性偏移** | 所有拍残差**一致** | 整条音轨相对视频偏早/偏晚 | 常数，源分析值与输出偏移分开记 |
| **抖动** | 残差随时间**散开** | 真的在漂移 | 去找原因，通常是某处帧数写死了 |

⚠️ 测量精度：8kHz 包络互相关对中文语音约有 **±2~3 帧的音节歧义**
（相邻音节波形相似，互相关可能锁错一个）。小于这个量级的残差无法与
测量误差区分，别拿它下结论。

### 从某一拍开始越走越偏

几乎只有一个原因：**代码里写了帧数**。

`src/VoxVideo.tsx` 和 `src/Root.tsx` 里的所有帧数都绑定 `timeline.json`。
如果你在某个组件里写了 `durationInFrames={90}`，那一拍就和旁白对不上了。

**改法**：不要在代码里调帧数。改 `script.json` 的 `rate`（语速）或
`padAfter`（气口），然后重跑 `npm run tts`。

### 片尾旁白被截掉几秒

**加转场时最常见的事故。** 转场让相邻两拍交叠，画面总长会变短，但音频
不参与交叠——如果没让气口装得下交叠，片尾的旁白就会被静默截掉。

`vox_tts.py` 的处理是：每拍尾部留白取 `max(padAfter, 下一拍的 transitionFrames)`，
并且 `from` 走**视觉时钟**（每拍推进 `durationInFrames - 下一拍 transitionFrames`），
音频再按这个 `from` 绝对摆放。正常流程下不会出这个问题；**但如果你手改过
`timeline.json`，就会**。

自查：`verify_sync.py` 的表格里出现巨大负数（比如 -1942 帧）就是它——
那一拍的音频起点被推到了成片长度之外。

### 画面比旁白越来越早 / 片尾一大段空白

同一个根因的另一种表现。`from` 如果按音频时钟累加（`cursor += dur`），
而视觉走 `TransitionSeries`、每拍都会被下一个转场吃掉 `te` 帧，那么画面
会逐拍提前：13 拍 × 10 帧 = 132 帧（4.4 秒），片尾再空出同样长度。

**`verify_sync.py` 查不出来**——它只比字幕和音频，两者都记在同一个 `from` 上，
自然一致。只能靠看画面判断：抽尾帧（`--frame=<totalFrames-30>`）如果是空白纸，
就是它。

正确的累加是 `cursor += dur - next_te`。改完必须重跑 `npm run tts` 再重渲，
成片会短掉"转场总帧数"那么多，这是修复而不是丢内容。

### 字弹出的时机对不上声音

检查 `script.json` 里这一拍的 `visual.words` 和 `narration`：

- **词序不同** → 对齐会退化。`resolveWordTimings` 按顺序查找，词换了位置
  就找不到。改成和旁白一致的词序。
- **上屏词比旁白长** → 只能按旁白时长均匀铺开，不会卡词。
- **`visual.words` 写成了摘要而非原文** → 例如旁白是"一枚只有3.8公斤的
  探测器"，上屏写"轻"，这两个字在旁白里找不到位置。

差半帧不用管（TTS 的 boundary 本身就是 100ns 精度换算过来的）。
差一拍以上才是词序问题。

**每个镜头开头半秒空屏**（字总比声音晚到）：这是模板内部的对齐规则，不是稿子的问题。检查 `src/words.ts` 的 `resolveWordTimings` 是否还在
匹配前剥掉标点——上屏词按旁白标点切成 `"有一种三角形，"`，而 edge-tts 的词流
没有标点，两侧不剥就永远匹配不上，只能退回"按区间均匀铺开"。改这一处等于改
全片的对位，改完必须抽镜头第一帧复看。

### 改了旁白但声音没变

`vox_tts.py` 用「旁白+音色+语速」的 SHA1 做指纹判断缓存。
如果你手工改过 `public/audio/*.mp3`，缓存可能对不上。用 `--force` 强制重合成：

```bash
python "<skill>/scripts/vox_tts.py" --project "<项目>" --force
```

强制重做某一拍（其余拍按指纹走缓存；但如果别的拍文案也改过，会一并重合成）：

```bash
python "<skill>/scripts/vox_tts.py" --project "<项目>" --only hook
```

### 数字滚到一半才念出来

StatCard 的计数起点跟着旁白走。旁白把数字放在句尾时，滚动就没时间了。
**把数字移到句首**："五年，很多家庭的路由器就没换过了。" 而不是
"现实是，很多家庭的路由器，用了五年还没换过。"

### 管线偏移换版本后变了

实测（Remotion 4.0.535 / H.264+AAC / 1080p30）：系统性偏移 **0 帧**，
逐拍抖动 **±0.02 帧**。所以这条管线不需要补偿。

但这个结论**由「Remotion 版本 + 编码 + 采样率 + 容器」共同决定**，
任一变化都必须重量一次，别照搬。

## 渲染报错

| 报错 | 原因与处理 |
|---|---|
| `RangeError: Frame NaN is not finite` | `spring()` 收到了 NaN。`src/words.ts` 的 `safe()` 已做防护（`BeatPresence` 从那里导入）；自己写组件时，喂进 `spring` 的每个数都先过一遍 `Number.isFinite` |
| `Malformed path data: M was expected to have numbers` | `clockWipe` / `iris` 需要画幅尺寸。无参调用时 Remotion 4.0.535 内部算出 `NaN` 半径，生成 `M NaN…` 路径，崩在渲染那一帧。模板的 `transitionFor()` 已统一喂尺寸；自己直接调这两个转场时也要传 `width` / `height` |
| webpack 解析失败，错误信息巨长（列举所有尝试的后缀） | `src/components/` 下导入 `src/theme` 必须写 `../theme`，不是 `./theme` |
| `Cannot find module './timeline.json'` | 没跑 `vox_tts.py`，或 `script.json` 解析失败。scaffold 会先放一份占位 timeline，所以正常不会遇到 |
| 首帧闪一下 / 资源没就绪 | `<Sequence>` 少了 `premountFor`。模板里都加了 30 帧，新加的 `<Sequence>` 也要加 |
| `StillProps: Property 'fps' does not exist` | `<Still>` 不接受 `fps` 参数，只有 `<Composition>` 接受 |
| 中文字掉字 / 闪一下 | 字体没等加载完。见下节 |

### 改了代码但画面没变

Remotion 有缓存。强制重建：

```bash
npx remotion render VoxVideo out/video.mp4 --rebuild
```

或者直接删掉项目的 `node_modules/.cache`。

## 字体

模板用两套（见 `src/fonts.tsx`）：

| 用途 | 字体 |
|---|---|
| 中文标题 / 要点 | Noto Sans SC **900**（靠字重造层级） |
| 正文 / 说明 / 字幕 | Noto Sans SC 400/700 |
| 数字 / StatCard | Archivo Black |

**字体文件在 `public/fonts/`，由 `FontGate` 用 `delayRender` 挡住首帧。**

不要换回 `@remotion/google-fonts`：中文字体在 Google Fonts 上按 unicode-range
切成 120 个分片，只请求 `subsets: ["latin"]` 时拉丁正常、中文**静默回落**到
系统雅黑——日志里只有一句 "font loaded"，屏幕上却是细黑体，整片立刻像 PPT。
真要把分片全拉下来则是几千个请求，首帧会卡很久。

站酷庆科黄油体（ZCOOL QingKe HuangYou）试过又撤掉了：它是细几何体，40–60px
下中文笔画糊成一团，标题读起来像乱码。装饰性展示体只适合极大的单句。

数字别用 numeral 字体排中文：Archivo Black 没有汉字，会掉到雅黑常规体，
字重和旁边的标题对不上。用 `fontFor(text)` 判断。

## 视觉问题

### 内容压到左上角角标

新增组件时保留了模板的上下 padding（`140px / 130px`）就不会出现。
参考 `components.md` 的布局分区表。

### 整片只有一个色调，很闷

强调色按 `ACCENT_CYCLE`（`theme.ts`）逐拍轮转。相邻两拍同色会显得平，
把 `ACCENT_CYCLE` 的顺序打乱，或往里加颜色。

### 配图拍整体发品红

`AmbientLight` 的 accent 色斑压在照片上：照片本身有色彩，再叠一层品红/橙色
混合模式，整拍的色调就偏了。模板对有 `image` 的拍自动关闭 `AmbientLight`；
自己改过 `visuals.tsx` 的话，检查那一拍是不是漏了这条判断。

### 某一拍迟迟不出东西

如果这一拍的视觉内容依赖旁白里出现的词，而那些词找不到，就会落到
"均匀铺开"的兜底分支，最后一项落在整拍时长的尾端。检查内容是不是
真的在旁白里出现过。实在对不上就把关键内容挪进旁白。

### 手写拍字太小 / 不像手写

- 单行超过 12 字会自动缩字号，手也跟着缩；拆成两行或删到 10 字以内。
- 拍短写不完时组件会加速（最多 2 倍速）；还挤就说明这句话该拆成两拍。
- 字是**逐字显影**，不是逐笔绘制（中文笔顺要解析字体轮廓，运行时做不到）。
  想更像手写就调低 `write.speed`（1.5-2.5 字/秒），不要靠缩小字号硬塞。

### 首拍太素

第 0 拍自动是深色底 + 片名角标。用 `kind: "kinetic"` 配一个
2-4 词的 `words` 和一个 `emphasis`，冲击力最足。

### 字幕只剩半句，中间大段没有字幕

`CaptionTrack` 的断句把**软断点（句内逗号）当成了句子终点**：
遇到第一个逗号就把 `end` 定死，后面真正的句号到来时因为 `end` 已经
有值，整句被截成第一个逗号前那几个字。

症状是字幕只显示「到头来，」这种半句，而且只有开头一小段有字幕。
软断点应该只是**候选**：句子没超长就一直等到句末，超过 `SOFT_MAX`
才在最近的逗号处断开。

顺带一个更隐蔽的坑：edge-tts **不把标点作为独立 boundary 输出**
（`words` 拼起来 = narration 去掉所有标点）。所以用 narration 的下标
去查一个"跳过标点后"的紧凑数组，第一句之后就整体错位。
`buildCharMap` 必须返回与 narration **同下标对齐**的数组，标点位置存 `null`。

### 圈注画成了好几个框

`visual.circled[0]` 是一个**字符串**，但循环写成了
`for (const c of circled ?? [])`——那是在逐**字符**迭代，
"不是没钱"被拆成 不/是/没/钱 四段，于是画了四个框。

要按短语匹配就写 `for (const c of circled ? [circled] : [])`。

### Odometer 的数字被裁掉一半

格子 `height: 150`，但内部每行用了 `height: "10%"` = 15px，
里面塞 110px 的字，被 `overflow: hidden` 裁成半截。

**行高必须等于格高**（都用 px），整条 strip 用
`translateY(-值 × 格高)` 位移。用百分比做行高在这里永远是错的。

### 计数过程中整排数字左右挤

`Math.floor(shown).toLocaleString()` 在位数变化时（"2,000" → "200,000"）
整排会往左挤，像镜头在推。列数应该由**最终值**决定，
当前值补零到同样位数再逐位填进去。

### 旁白还在说，画面已经定格（像 PPT）

```bash
python "<skill>/scripts/check_motion.py" --project "<项目>"
```

看**逐拍均差**列。`<1.5` 的拍就是死拍：观众听到的还在推进，看到的已经停住。
本片实测 13 拍里 6 拍不合格，问题精确到 beat 名和组件类型，不用再靠感觉猜。

三个常见原因，按出现频率：

1. **组件动画提前跑完**。`TimelineRail` / `Route` 的进度由
   `resolveWordTimings` 驱动，最晚那个节点亮起之后整拍就静止了；而旁白往往
   还要说两三句。补法：轨道加巡游光点、地图点位加扩散的雷达波
   （模板已内置这两处）。
2. **入场动画是"一次性"的**。卡片落位、文字弹完就归位。补法：落位后叠一个
   低频浮动（`floatAt()`，各元素相位错开），观众说不出哪里在动，但画面就"活"了。
3. **整拍只有静态排版**。`chart`、`compare` 这类信息图最容易。补法：让数据
   在旁白念到对应项时再补一次强调动画，把动作拆到整拍上。
4. **构图太空**。`timeline` / `route` 这类图只占画面中间一小块，四周全是纯色底，
   元素动得再多也被大面积静止像素摊平。本片实测：`route` 的地图从 1640×780
   内嵌卡片改成整幅铺满（网格铺底、点位与标签放大 20%、标题移到右上避开角标），
   均差 1.32 → 1.70；`cards` 卡片拉到整幅高度、`compare` 双栏改 `space-between`
   撑满后 1.32 / 1.27 → 1.59 / 1.70。**这一步的收益比加动作大一个量级。**
5. **对比度太低**。换成纸艺拼贴之后全片从 2.00 掉到 1.78：纸片是近白、底纸也是近白，
   元素移动时像素几乎不变。修法不是加动作而是**加深底纸**（`COLORS.stage`
   #E9E2D2 vs 纸片 #FFFDF6），同一套运动会立刻重新被测出来。
   同理，**软渐变救不了帧差**：背景光斑漂移从 18px 加到 58px，均差只涨 0.02。
6. **数字/文字一次性出现**。整块淡入 = 变化只发生在几帧里。改成逐字落位
   （`Person` 姓名）、年份滚动（`TimelineRail`）、里程碑做成纸片，变化的帧数立刻翻倍。
7. **大面积平涂没有持续变化**（纸艺、扁平插画都会）。均差能过线，但"近乎静止帧"
   仍然占 70% 以上。补法：整幅低频漂移（`sway()`）+ 几粒缓慢上浮的纸屑尘埃 +
   极轻的曝光呼吸，都在 `PaperStage` 里，不要另写一套。

### 画面一直在抖 / 整片像在颤

先分清是**位移抖**还是**亮度闪**：

| 症状 | 来源 | 修法 |
|---|---|---|
| 整幅、所有元素一起高频跳 | 整幅用了 `jitter()`（每 2-3 帧重摆 2.5px） | 换成 `sway(frame, seed, 6, 240)`，连续正弦，读作"纸张在呼吸" |
| 每张卡片/每个标签各自跳 | `PaperSheet` / 组件里的 `jitter()` | 换 `sway()`，幅度 1-2px、周期 150-200 帧；只在个别小标签保留 `jitter` |
| 整片亮度在闪 | 曝光呼吸幅度过大或换得太快 | 幅度收到 0.4%-2.0%、`hold` 放到 3-4 帧。1% 左右肉眼几乎看不出 |
| 只有某一拍在震 | 那一拍配了 `impact` | 冲击是**一次性**的，检查是不是被 `ambient` 拖成了持续抖动 |

面积决定观感：同样 2px 的位移，一个小标签上是"手工感"，铺满全幅再加几十个元素
就是"手抖镜头"。**整幅一律用 `sway`，`jitter` 只留给小面积。**

代价要说清楚：去掉整幅抖动后，`check_motion.py` 的"近乎静止占比"会从 39% 回到 60%。
这个数字奖励的正是那种颤动，**不要为了它把抖动加回来**。

> **关于"近乎静止占比"这个指标本身**：它按 `<2.0` 的帧均差计数，本质在量
> "整幅面积上的变化量"。实拍/纸艺参考片能到 2-9%，靠的就是传感器噪声和材质
> 颗粒——那不是"动得好"，是"每一帧都是新拍的照片"。用纯 CSS/SVG 复现，
> 唯一等价的手段就是给整幅加噪声/颤动。
>
> 所以 `check_motion.py` **默认不拿它判失败**，只打印参考值（要当闸门加 `--strict`）。
> 纸艺风格稳定在 60% 左右是正常的：能压到 30-40% 的版本都带着整幅抖动，
> 观感是"画面在颤"，不值得。

改完**必须重跑 `check_motion.py` 对比**，别改完就算完——肉眼对 1.3 和 2.0 的差别
几乎没有分辨力。

**调幅度要适可而止。** 实测把浮动振幅从 4px 翻倍到 8px，6 个死拍平均只从 1.40
涨到 1.47。原因是帧均差是**全画幅平均**：画面大面积是纯色，一小块文字浮多远
都摊薄到看不见。真要让数字上去，得让主体占满画面（改构图），或者换成
i2v 素材（元素本身的纹理在动）。继续加到 15-20px 只会看起来像船在晃。

> **别拿参考片的 9% 当及格线。** 纸艺/实拍参考片静止帧 2-9%，靠的是传感器噪声和
> i2v 元素运动。纯平涂矢量画面同一段运动在 192/384/960 三种采样分辨率下测出来
> 几乎一致（已排除降采样因素），只靠元素运动的天花板就在 2 附近。纸艺层内置了
> 漂移 + 尘埃 + 曝光呼吸，稳定在 60% 左右；再往下只能靠整幅颤动，别追。
> 判据以**逐拍均差**和**改版前后对比**为主。

> `visual.ambient` 只负责消灭"整段完全不动"，幅度受 4.8% 推近上限约束，
> 救不了死拍。要活泼必须动组件。

### 成片里有横向残影，文字叠成三四个

`mix-blend-mode`（`soft-light` / `overlay`）的元素如果有一个带 `transform` 的祖先
（纸艺层的定格抖动就是），Chromium 会走合成层缓存，只重画"脏矩形"，
留下一串前几帧的残影——**静帧抽出来完全正常，只有成片里才看得见**。

触发条件：`LightSweep` / `AmbientLight` 的 `mixBlendMode` + `PaperStage` 的
`transform: translate(...)` 包装层。修法是把混合模式去掉，改用普通 alpha
（`LightSweep` 现在是 0.16 白色渐变，`AmbientLight` 是 `opacity: light * 0.8`），
视觉差别很小。

> 这类问题只能靠**抽静帧时挑在动画中途**发现。渲染完不要只看封面那一帧。

### 纸片没有投影，或者投影把里面的字也复制了一份

影必须放在**背景层**：

- `box-shadow` 会被 `clip-path` 一起裁掉 → 毛边纸片等于没有影；
- 放在外层容器上（`filter: drop-shadow`）→ 卡片里每个字都会投一道影，读起来全是重影。

`PaperSheet` 的做法是单独一层绝对定位的底色 `div`，`clip-path` + `filter: drop-shadow`
都挂在它身上，内容放在上层。自己写新组件时照抄这个结构。

### 纸片边缘的毛边看不出来，或者大片纸出现缺口

`roughEdge(seed, amp)` 的 `amp` 单位是 **px**，不是百分比。用百分比抖动时，
小纸片看不出、大纸片（半屏）会缺掉几块。默认 `amp = 2.4`、`step = 8`（%）。
胶带这类窄元素用 `1.8 / 6`，大背景纸屑用 `5 / 9`。

### 分层背景板：远层看不见 / 主体被水平切断 / 叠起来像三张不同的画

- **远层被中景盖住**：`layers` 的每条带默认都落在画面底部，必须给 `y`
  （这条带在画面上的位置，0-1 从上到下）。远层给 `y: 0.22`、中景 `0.38`、近景 `0.76`。
- **旗帜、人物头被水平切断**：裁切是**从原图底部往上取**的，出图时主体必须落在
  原图底部那条带里，提示词要写"主体全部位于画面下方 X%，上方是空白米色纸（会被裁掉）"。
- **叠起来像三张不同的画**：三层的 `light`（光源方向）和 `color`（色调）必须一致，
  照抄同一份 brief 的这两项。
- **层比整幅图还平**：给每层不同的 `depth`（0 远 → 1 近），远层几乎不动、近层跟着底纸走。
- **人像拍的圆形头像被横带切开**：`person` 拍的圆形剪影正好在画面左侧中段，
  任何横着的背景带都会从中间切断它。这种拍要么用整幅背景（不给 `band`），
  要么把带压到头像下方（`y` ≥ 0.72），要么干脆不用背景。
- **大数字拍留白最好**：`stat` 拍别加图，也不要用分层背景。
- **图里多出蓝色地面 / 写实泥土**：模型会自作主张加"水/泥地"。brief 里要显式禁止：
  "墙脚以下仍是一整张米色纸""不要写实的泥土裂纹"。出了这种图就改 brief 重出，
  不要靠裁切救——裁切只能从底部取，躲不开。
- **底带裁切躲不开中间的东西**：要保留原图**中间**的一段（不是底部），
  现在的 `band` 模型做不到，只能重新出图（把主体画到底部那条带里）。
- **怎么写"不要写实地面"都不听**：Z-Image 只要场景里有"地面/路面"，
  就会加沙砾、枯草、真实泥土。绕法是**换掉场景本身**——不写"低机位贴地"，
  改成"一张赭色纸带平放在米色纸桌面上"，它就只会给纸。两次失败后换场景描述
  一次就成。
- **"主体只在左下角"也不听**：模型会把同样的东西补到右边，中间留一道硬缝。
  这种构图要求只能靠"整幅用"或干脆不用，别指望裁切救。

## 运镜层：右侧露出竖直色带 / 平移露黑边 / 甩镜切字

**症状**：加了 `camera: "pan"` 或 `"whip"` 之后，画面右侧出现一条**竖直的色带**
（底色比别处深或浅），或者平移到某一帧时边缘露出黑边。

**原因**：`AmbientLight` 的渐变块和画幅一样大。运镜是"放大 + 平移"，
渐变块被平移后，它的边缘就被甩进画里了。背景渐变是无限延伸的，
盒子必须比画幅大一圈。

**修**：`AmbientLight` 的外层加 `inset: "-30%"`（盒子放大到 1.6× 画幅）。
平移类的 `camera` 另外要用足够大的放大留出血：

| move | 基础放大 | 行程 |
|---|---|---|
| `pan` / `tilt` | 1.06 | 4-5% |
| `parallax` | 1.08 | 8% |
| `whip` | 1.2 | 18% |

**平移绝不能靠仿射位移硬凑**——必须从 overscan 画布取样，否则会露出画布外的黑边。
这是从别人的踩坑记录里抄的规矩。

**甩镜切字**：`whip` 行程大，会把画幅边缘的内容切掉。甩镜只用在
"内容本身就贴着中心"或"切章"的拍上，慎用。

## 冲击放射盖住了大字

**症状**：`vfx: "starburst"` 之后，画面先看到一圈黄线，文字反而看不清。

**原因**：放射线画在了内容层**上面**，而且透明度太高（0.85）。

**修**：两处一起改——

1. 把它挪到**内容层下面**（`visuals.tsx` 里放在内容 div 之前）
2. 透明度压到 **0.42**、线宽减半、半径 0.46

原则：**放射线是"背景里炸开"，不是"盖在画面上的一层黄"**。

## 转场时整幅闪一记橙黄（像反相）

**症状**：某两个拍之间有一两帧整幅变成橙黄/反相，看起来像渲染错误或色彩 bug。

**原因**：用了 `transition: "dissolve"`。Remotion 4.0.535 的 `dissolve` 是按
**亮度**决定"烧到哪"的烧灼转场（默认 spread `#ff0000` / hot `#e6e633`）。
平涂纸面的亮度几乎一致 → 所有像素同时越过阈值 → 整片一起烧起来，
中间没有"逐渐扩散"的层次。

**修**：软切换改用 `fade`。`dissolve` 留给有真实明暗层次的实拍图；
真想要烧灼感用 `filmBurn`（它带方向，不会整屏一色）。

验证方法：`remotion still --frame=<转场中间那一帧>` 抽一张，别只看预览播放。

## 碎片拼贴：块飞进来和底图重影 / 接缝漏一条浅色直线 / 右半幅变空白

这三个症状一个比一个隐蔽，都是"看起来像渲染 bug，其实是参数或写法"。

### 块飞进来和底图重影（洞没挖开）

**症状**：`pieces` 已经写了，块也在动，但底图**整张还在**——飞进来的块和它叠成
双影，而且**控制台一个字都不报**。

**原因**：挖洞写法不生效。实测两种都不行：

- `maskImage: url("data:image/svg+xml;charset=utf-8,...")` —— 静默失效
- 内联 `<svg><mask id="...">…</mask><image mask="url(#...)"/></svg>` —— 也不遮

两者在 Remotion 的 Chromium 里都会"当作没有"，既不报错也不遮。排查时最容易
走错方向：你会以为是 `pieces` 没生效，其实是洞没挖开。

**修**：用 `clip-path: path(evenodd, "外层矩形 + 每个洞一个子路径")`，画幅 px 坐标：

```tsx
const outer = `M0 0 H${width} V${height} H0 Z`;
const holes = pieces.map(p =>
  `M${p.x * width} ${p.y * height} H${(p.x + p.w) * width} ` +
  `V${(p.y + p.h) * height} H${p.x * width} Z`).join(" ");
// clip-path: path(evenodd, `${outer} ${holes}`)
```

替换后先用 `at: 999`（块永远不进场）渲一张：**画面应该是纸 + 几个洞**，
不是整图。这一步能立刻区分"洞没挖开"和"块没动"。

### 接缝漏一条从上到下的浅色直线

**症状**：几块都落位之后，接缝处有一条 1px 的浅色直线（纸色），整幅看起来
像被拼起来的截图。

**原因**：块严格拼满画幅，浏览器按小数像素裁切，边界偶尔差半个像素，漏出
底下纸色。

**修**：每块向外扩 `PAD = 0.004`（画幅比例，1920 宽下约 7.7px）让相邻块**互相
重叠**——重叠区取的是同一片源像素，所以看不出来。注意：

- 扩的是**画出来的盒子**，取景窗（`backgroundSize` / `backgroundPosition`）
  要跟着改，公式是 `p = −rx / (1 − rw)`；写成 `(x − rx)/(1 − rw)` 只有 `x=0`
  的块是对的
- 块飞行的**投影要在落位时淡到 0**，否则上层的投影会横过邻居的边，比缝还显眼

### 右半幅变成一片空白纸

**症状**：左边的块正常，右边的块**整块显示错位置**（常常是整片空白纸）。

**原因**：`background-position` 的百分比公式推错了。它不是"源图左边减盒左边"，
而是按**盒子和图之间的空档**算的：

```
offset = p% × (盒宽 − 图宽) = p% × F(1 − rw)
要 image 左边钉在画幅 0 处 → offset = −rx·F
→ p = −rx / (1 − rw)
```

`x = 0` 的块两种写法结果一样，所以左边对、右边错——这个现象本身就是线索。

另外还有一个容易漏的：`PieceLayer` 是挂在 `PaperStage` 的**底纸容器**里的，
那个容器为了漂移是 `inset: -STAGE_INFLATE`（-14px）。在里面按画幅百分比定位
会整体放大 1.5%、右下角偏出十几个像素。根节点要写 `inset: STAGE_INFLATE`
减回去，否则接缝永远差一点。

## 配乐：听不清旁白 / 音乐没进来 / ducking 没生效

**音乐没进来**：检查三处——`script.json` 里的 `music.src`（相对 `public/`）、
文件真的在 `public/` 下、`npm run tts` 重跑过（`timeline.json` 里要有 `music`）。
`preflight.py` 会检查配乐文件在不在。

**盖过人声**：`gain` 太大或 `duck` 太小。默认 `gain 0.2 / duck 0.6`。
人声是主旋律，配乐是底。`preflight.py` 在 `gain > 0.45` 或 `duck < 0.4` 时会提醒。

**想验证 ducking 真的生效**（别靠耳朵判断，人耳对 6dB 的差不敏感）：

1. 造一条**恒定包络**的测试音床（220Hz 正弦 + 少量谐波，无 LFO）
2. 渲两遍：一遍带音乐、一遍把 `timeline.json` 里 `music.gain` 改成 0
3. 两遍的音频相减 = 纯音乐轨
4. 比较说话段和间隙段的 RMS

实测说话段 600、间隙段 1390，比值 2.18（期望 1/(1−duck) = 2.63）。
比值明显 > 1.3 就说明让路生效了。

> 顺带一提：直接比较整段混音的 RMS 是**测不出来的**——说话段里人声占主导，
> RMS 反而更高，看起来像"音乐更响了"。必须做差分。

## 组件代码漂移：项目跑的还是旧组件

改了 skill 里的 `assets/template/src/`，项目没跟着变（"为什么这个项目没有新功能"），
或者在项目里改了组件，别的项目拿不到。

别手工拷文件——一不小心就把 `script.json`、`src/timeline.json`、`public/img`
这些项目私有的东西一起拷走。用同步脚本：

```bash
python "<skill>/scripts/sync_template.py" --project "<项目>" --check    # 先看差异
python "<skill>/scripts/sync_template.py" --project "<项目>" --push     # 模板 → 项目
python "<skill>/scripts/sync_template.py" --project "<项目>" --pull --force  # 项目 → 模板
```

`--check` 有差异时退出码是 1，可以进 CI。`--pull` 会先备份被覆盖的模板文件到
`assets/template/.backup/<时间戳>/`。

改了 `src/` 之后要重新渲染才看得到；时间轴没变就不用重跑 `npm run tts`。

## TTS 与环境

### 音色

默认 `zh-CN-YunjianNeural`（男声，解说片常用）。其他可选：

| 音色 | 感觉 |
|---|---|
| `zh-CN-YunjianNeural` | 沉稳男声，默认 |
| `zh-CN-YunxiNeural` | 年轻男声，更活泼 |
| `zh-CN-YunyangNeural` | 播音腔，新闻感 |
| `zh-CN-XiaoxiaoNeural` | 女声，温柔 |
| `zh-CN-XiaoyiNeural` | 女声，活泼 |
| `zh-CN-YunxiaNeural` | 男童声，亲和 |

### 语速

`rate` 默认 `+12%`。中文 TTS 的基准语速对解说偏慢，加 10-15% 才有
VOX 的紧凑感。**超过 `+20%` 中文会开始吞字**，观众会听不清。

语速变了以后**所有拍都要重新合成**（缓存指纹包含 rate），这会多花一点时间，
但省得逐拍 `--only`。

### 中文 TTS 的标点

`narration` 里用中文标点断句，word boundary 会按标点切。避免在
`narration` 里用引号、括号、斜杠——它们会被念出来或者念得很怪。
这些符号可以放在 `visual` 字段里（那些不会被朗读）。

### edge-tts 装不上

`vox_tts.py` 会自动在项目下建 `.venv-tts` 并安装 edge-tts，不需要手动处理。
如果自动安装失败，手动执行：

```bash
cd "<项目>"
python -m venv .venv-tts
.venv-tts/Scripts/python -m pip install edge-tts
```

### TTS 偶发失败

脚本对每拍重试 3 次（退避 1.5s / 3s / 4.5s）。并发默认 4 路，edge-tts
有速率限制，段数特别多（>40 拍）时可以降并发：

```bash
python "<skill>/scripts/vox_tts.py" --project "<项目>" --concurrency 2
```

### 找不到 ffprobe

量音频时长用的是 Remotion 自带的 ffprobe（`node_modules/@remotion/compositor-*/`）。
如果报"找不到 ffprobe"，说明依赖没装好，跑一次 `npm install`。
系统 PATH 里有 ffprobe 也会被识别。
