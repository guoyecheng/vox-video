# 叙事弧与分镜节奏

写稿之前先选一条弧。弧决定 beat 的**顺序和形状**，组件决定 beat 的**长相**——
这两件事分开，想清楚前者再写后者。

## 怎么用

1. 看主题属于哪一类 → 查表挑一条弧（`topic → arc`）
2. 按弧的 beat 形状列 beat 表（`id` 用阶段名，方便对着看）
3. 拍数和每拍长度按下面的数字表卡（长度是量出来的，不是拍脑袋）
4. 第 1 拍从 hook 句式库里挑一个
5. 每拍再定三根杆：**镜头怎么动**（camera）+ **内容怎么进场**（motion）+ **摆在哪**（layout）

## 叙事弧库

| 弧 | 什么时候用 | beat 形状 |
|---|---|---|
| `hook_payoff` | 讲一个概念，最保险的默认 | 钩子 → 背景 → 铺开 → 兑现 → 收束 |
| `how_it_works` | 讲机制、原理、系统怎么转 | 钩子 → 它是什么 → 2-3 步拆解 → 有什么用 → 收束 |
| `timeline` | 历史、演变、一路走来 | 起点 → 事件 → 事件 → 转折 → 今天 → 结论 |
| `chronicle` | 史料型叙事（本片这类） | 命题 → 事实铺陈 → 反转/崩塌 → 归因 → 落点 |
| `man_in_hole` | 案例、翻身、跌落再起 | 还行 → 掉下去 → 更深 → 爬出来 → 比从前更好 |
| `myth_buster` | 纠正一个误解 | 先给事实 → 说那个误解 → 拆穿逻辑 → 该信什么 |
| `three_act` | 任何 60 秒叙事片 | 铺垫 → 冲突（上升） → 收束 |
| `origin` | 创始人、"我们为什么做这个" | 世界 → 一个念头 → 跃迁 → 挣扎 → 突破 → 今天 |
| `story_spine` | 使命、信念、品牌故事 | 曾经… → 每天… → 直到某天… → 因为… → 直到最后… |
| `pas` | 痛点型广告 | 问题 → 放大 → 方案 → 证据 → 行动 |
| `bab` | "以后"比"以前"更打动人的广告 | 以前 → 以后 → 桥 → 行动 |
| `aida` | 冷启动付费投放 | 注意 → 兴趣 → 欲望 → 行动 |
| `listicle` | 清单、技巧、排名 | 承诺 → 条目 1 → 条目 2 → … → 第一名 → 回顾 |
| `story_circle` | 人物驱动的 UGC / 品牌片 | 你 → 需要 → 出发 → 寻找 → 找到 → 带回 → 改变 |

**主题 → 弧**：
概念/机制 → `how_it_works` / `hook_payoff`；历史/演变 → `timeline`；史料叙事 → `chronicle`；
案例/转型 → `man_in_hole`；纠错 → `myth_buster`；产品/服务 → `pas`/`bab`/`aida`；
排名/技巧 → `listicle`；创始人 → `origin`；品牌使命 → `story_spine`；通用 60 秒叙事 → `three_act`。

## 拍数与长度

| 总时长 | 拍数 | 每拍 | 旁白字数 |
|---|---|---|---|
| 30s | 6-8 拍 | 4-5s | 70-85 字 |
| 60s | 10-13 拍 | 4-6s | 130-160 字 |
| 90s | 14-18 拍 | 4-6s | 200-240 字 |

**每拍不超过 ~6 秒**。更长的拍有两个问题：画面没有变化点，注意力掉；旁白太长，
一句话塞太多观点，观众记不住。一拍讲一件事——想讲两件就拆成两拍，拆开不花钱。

**别用静画面超过 8 秒**。每一拍内部都要有持续的动（见下面三根杆），
这是"看起来信息密度高"和"看起来是 PPT"的分水岭。

## Hook（前 3 秒）

约 65% 的观众在前 3 秒决定要不要继续看。**第 1 拍不许铺垫**，直接给最反直觉的那个事实。
九种句式，挑一种：

`mistake_callout`（你以为…其实…）· `pain_point`（戳中一个具体的烦心事）·
`surprising_stat`（一个反常识的数字）· `direct_question`（直接问）·
`urgent_warning`（不这样做会出事）· `secret_reveal`（行业里没人说的）·
`experiment_story`（我试了，结果…）· `pattern_interrupt`（打断一个默认预期）·
`outcome_tease`（先给结果，再讲怎么做到的）

Hook 拍的画面只放**一个**大字，不要塞卡片和数字。

## 全片比例

| 段 | 占比 | 说明 |
|---|---|---|
| Hook | 1-3 秒 | 只占开头，别拖 |
| 主体 | 70-80% | 铺开讲 |
| Payoff | 10-20% | 兑现 hook 里的那个承诺 |
| 收尾 | 0-2 秒 | 见下面三种收法 |

## 收尾形态

| 形态 | 做法 | 适合 |
|---|---|---|
| `hard_cut` | 兑现的那一刻直接切黑 | 默认；最利落，利于重播 |
| `quick_cta` | 结尾 2 秒内一句话 + 一个动作（3-5 个字） | 需要引导关注/点击的 |
| `loop_close` | 最后一句和第一句呼应成环 | 短片/社媒，循环播放 |

## 三根杆：镜头怎么动 × 内容怎么进场 × 摆在哪

这是"信息密度"的引擎。三根杆分开想——只做镜头运动，画面还是死的；
只做内容运动，镜头是死的；每页都居中，整片像 PPT。

**杆一：camera（整幅怎么动）**

| 值 | 效果 | 什么时候用 |
|---|---|---|
| `push_in` | 缓慢推近 | 默认；最不惹眼 |
| `pull_out` | 缓慢拉远 | 揭示、收束、"其实还有更大" |
| `pan` | 横移 | 横向扫过一组并列的东西 |
| `tilt` | 纵移 | 纵向扫过（上→下） |
| `parallax` | 带层差的横移 | 有前景遮挡物的画面（比 pan 更有纵深） |
| `whip` | 快速甩镜 + 方向性模糊 | 换章、卡点，慎用 |
| `static` | 不动 | 点题段、留白段；**相邻两拍不要都 static** |

**杆二：motion（内容怎么进场）**

| 值 | 效果 | 什么时候用 |
|---|---|---|
| `stamp` | 盖章：从 1.18 倍缩放压下来，过冲回弹 | 开场钩子、点题的"砸" |
| `wipe` | 揭开：内容从下往上卷开，不淡入 | 换章节、换场景 |
| `rise` | 升起：从下方 56px 升入 | 结论、落点（稳稳托出来） |
| `flip` | 翻页：绕 Y 轴翻正 | "翻到下一章"，只能手写 |
| `build` | 逐项搭：整幅不进厂，元素按词卡点逐个出现 | 并列清单（cards/timeline/route） |
| `drift` | 漂入：从右往左平移 | 配图拍、过场 |

**不写 `motion` 会按拍序自动轮换**（相邻拍保证不同）。自动轮换不会重复——
`check_rhythm` 报"相邻重复"一定是手写写重了。想精确控制就写，`flip` 必须手写。

**杆三：layout（同一组件换摆法）**

| 值 | 效果 |
|---|---|
| `center` | 组件默认：居中卡片 |
| `left-edge` | 靠左缘排版，打破每页居中 |
| `bottom-third` | 内容落在画面下三分之一，上方留给图 |
| `split` | 左右分栏（仅 stat：数字左、标签右） |
| `full-bleed` | 贴边排版（需要 `image`，文字压在图上） |

layout 不做自动轮换：连续多拍不写就是连续多张居中卡片，`check_rhythm` 会提示。
挑几拍写 `left-edge` / `split` / `bottom-third`，每页居中是 PPT 感的头号来源。

**相邻两拍的 camera_move 不要重复**——这是最省力的反单调手段。

**写 `visual.shots` 时，`motion` 和 `layout` 变成镜头级**（每个镜头各一份，
不写按全局镜头序号轮换）；`camera` 仍是拍级——镜头切的是内容层，纸台和运镜不动。

## 落进 `script.json`

```jsonc
{
  "arc": "chronicle",              // 选好的弧（写稿阶段定）
  "beats": [
    { "id": "hook",   "narration": "…", "visual": { "kind": "kinetic", "camera": "push_in" } },
    { "id": "buildup","narration": "…", "visual": { "kind": "cards",  "motion": "build" } },
    { "id": "landing","narration": "…", "visual": { "kind": "stat",   "layout": "split" } }
  ]
}
```

- `arc` 写在顶层，是给人看的（告诉用户这条片子按什么结构走）
- `visual.camera` 对应杆一，缺省按 `push_in`
- `visual.motion` 对应杆二，缺省按拍序自动轮换（相邻拍保证不同）
- `visual.layout` 对应杆三，缺省是居中卡片——挑几拍写别的
- `visual.elementMotion` 已降级为自由备注，不影响渲染

## 反单调清单（写完 beat 表过一遍）

- [ ] 相邻两拍的 `camera` 一样了吗 → 换掉
- [ ] 有没有连续三拍同一个 `kind` → 中间插一张别的
- [ ] 有没有把 `motion` 写成连续两个一样 → 不写就是自动轮换，写重了反而单调
- [ ] 有没有连续三拍都没写 `layout` → 挑一两拍写 left-edge / split / bottom-third
- [ ] 有没有拍超过 6 秒 → 拆
- [ ] 第 1 拍是不是在铺垫 → 换成反常识事实
- [ ] 结尾有没有兑现第 1 拍的承诺 → 对不上就改其中一边
